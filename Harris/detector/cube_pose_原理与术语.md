## 0. 这套程序到底做了什么

**输入**：一张单目相机拍的 BGR 图像（可选：YOLO 给出的目标框）。

**输出**（前提：画面里有个**边长已知的立方体**）：

| 输出 | 含义 | 单位 |
|---|---|---|
| `centerDist` | 相机到立方体中心的距离 | m |
| `center` | 立方体中心在相机坐标系下的 (x, y, z) | m |
| `cornersCam[0..7]` | **8 个角点的物理位置**（相机坐标系） | m |
| `vertexPos3D[i]` | 第 i 个被检测到的轮廓角点对应的物理位置 | m |
| `faces[0..2]` | 3 个可见面的**平面方程** `n·X = d` 和到相机的距离 | m |
| `topNormal` / `yawDeg` | 朝上那个面的法向 / 立方体的偏航角 | — / 度 |
| `verts[0..5]` | 6 个亚像素精度的图像角点（有序） | px |
| `reprojRms` 等 | 质量指标，用来判断这次结果可不可信 | px / — |

**一句话原理**：立方体在照片里的外轮廓**必然是凸六边形**，所以先抠出轮廓 → 取凸包 → 把凸包拆成直线段 → 相邻直线求交点得到 6 个有序亚像素顶点 → 拿这 6 个点和"已知边长的立方体模型"做 PnP，解出位姿，角点物理位置和平面方程都是位姿的直接推论。

## 1. 整体流程（对应代码里的顺序）

```
BGR 图像
  │
  ├─(1) ROI：有 YOLO 框就用它并外扩 15%；没有就全图 + 自动候选区域
  │
  ├─(2) 分割：把立方体从背景里抠出来 → 二值掩膜 (mask)
  │        4 种策略（Otsu / 自适应阈值 / Canny+闭运算 / Lab 色差）自动打分选优
  │
  ├─(3) 轮廓 → 凸包 (convexHull)
  │        立方体投影是凸的 ⇒ 取凸包后，内部的花纹、毛笔字、纹理全部被忽略
  │
  ├─(4) 凸包 → 若干直线段（fit-and-split 拆分 + 共线合并 + 短段剔除）
  │
  ├─(5) 相邻直线求交点 ⇒ 有序顶点（亚像素）
  │
  ├─(6) 亚像素精化：沿每条边的法向找 |灰度梯度| 的极值，重新拟合直线
  │
  ├─(7) 顶点数判定：6 → 三面可见（主力分支）；4 → 只看到一个面
  │
  ├─(8) PnP：6 个 2D 点 ↔ 立方体模型 6 个 3D 点 ⇒ 旋转 R + 平移 t
  │        多假设枚举（6 起点 × 2 方向 × 2 标注）+ 判据筛选
  │
  └─(9) 规范化输出：位姿换算到"z 朝上、x 朝右"的立方体坐标系
            ⇒ 平面方程、8 角点物理位置、测距工具
```

## 2. 为什么不用 Harris 角点（这条路的取舍）

很多人的第一反应是"Harris 找角点 → NMS → 两两连线 → 找平行线 → 连端点"。这条路**能跑，但很脆**，原因：

1. **组合爆炸**：n 个角点两两连线是 C(n,2) 条。Harris 在真实照片上给不出 7 个点，往往是几十上百个（边缘上也有响应），线对数量直接到百万级。
2. **平行 ≠ 棱**：立方体 7 个可见顶点有 21 条连线，只有 9 条是真正的棱，其余是面对角线/体对角线，它们**也成平行族**，会产生大量假四边形。
3. **透视下"平行"不成立**：立方体一个面上的对边只在正对相机时才平行，一般视角下它们交于**灭点**（见术语表）。所以正确做法是按灭点分组，而不是按"图像上平行"分组。
4. **端点配对有二义性**：两条线段 4 个端点有两种连法，一种得凸四边形、一种得自交蝴蝶形。
5. **角点响应 ≠ 顶点**：Harris 给的是"这个像素邻域的梯度在两个方向上都变化剧烈"，它沿边缘也会响应；而且如果立方体表面有深色花纹（比如本项目的毛笔字），花纹边缘同样会有强响应，噪音极大。

**反过来看轮廓法的好处**：一个真实的物理立方体，边界对比度通常远强于内部花纹；而"立方体投影是凸的"是几何定理，取凸包这一步天然把内部花纹全部忽略；直线拟合用到了整条边上的成百上千个像素（相当于做了上千次平均），所以顶点精度能到亚像素，而 Harris 峰值只能到像素级。

> 结论：**顶点应该是"两条棱线的交点"，而不是"角点响应最强的那个像素"。** 这是本程序最核心的设计选择。

## 3. 每一步在做什么、为什么这么做

### 3.1 ROI 与"外扩"

**ROI**（Region of Interest，感兴趣区域）就是"只在这个矩形框里找"。用 YOLO 的检测框有两个好处：算得快（像素少了），不容易被背景干扰物骗到。

**必须外扩**：YOLO 的框通常贴得很紧，而立方体的轮廓角点经常正好落在框边上，被切掉一个角以后就"不是六边形"了，程序会报 `顶点数 = 5` 或者位姿明显偏。所以默认把框向外扩 15%（`roiPad`）。若框真的很紧，可以调到 0.25。

**没有 ROI 也行**：程序会先按全图跑一遍，失败时用各分割策略得到的轮廓外接框作为候选区域再试几次（`autoRoi`）。实践中"有一个粗框"永远比"全图硬找"更稳。

### 3.2 分割：把立方体抠出来

分割的输出是一张**掩膜**（mask）：和原图一样大的二值图，白色=目标，黑色=背景。四种策略：

| 策略 | 原理 | 适用 |
|---|---|---|
| **Otsu** | 自动找一个灰度阈值，让"两类之间差别最大、类内差别最小" | 目标与背景亮度差别明显 |
| **自适应阈值** | 不看全局，每个小邻域自己算阈值 | 光照不均匀（有阴影、渐变） |
| **Canny + 闭运算** | 先找边界（Canny），再用形态学**闭运算**把边界连成封闭区域并填充 | 目标与背景**颜色接近但边界清晰** |
| **Lab 色差** | 把颜色转到 Lab 空间，算每个像素与"背景色"的距离 | 目标与背景**颜色**不同 |

程序把这几种的结果都算出来，按"凸性 × 面积占比 × 是否触边"预筛，再按"拟合出的多边形有多少像素真的压在图像边缘上"（**边缘支持度**）最终选优。这套"多假设 + 打分"的思路比"调一个万能阈值"稳得多。

> **Lab 色彩空间**：L 是亮度，a/b 是两个颜色对立轴。它的好处是"亮度"和"颜色"分开，所以比 RGB 更接近人眼感觉，做颜色分割更稳。

### 3.3 凸包：让内部花纹彻底失效

**凸包**（convex hull）可以用一个比喻：拿一根橡皮筋套住轮廓，松手，橡皮筋绷紧后的形状就是凸包。所有"往里面凹"的地方都会被绷直。

- 立方体的投影**一定**是凸的（凸多面体的投影必为凸集），所以凸包 ≈ 真实轮廓。
- 立方体脸上的黑色毛笔字、格子纹理、贴纸花纹，只会让掩膜内部"挖洞"或让边界"凹进去一点"，**凸包会把这些凹口全部忽略**。
- 即使花纹压在棱边上（我们专门测试过这种情况），凸包也只会把那个凹口绷直，误差只有一两个像素，不会毁掉整个结果。

这就是为什么"内部有强烈花纹"对本程序几乎无害，却是 Harris 路线的灾难。

顺带得到两个质量指标：
- **solidity（凸性）** = 轮廓面积 / 凸包面积。立方体应接近 1（实测 0.99）。远小于 1 说明掩膜抠坏了或目标不是凸的。
- **是否触边**：轮廓贴着 ROI 边界 ⇒ 被切掉了 ⇒ 结果不可信。

### 3.4 凸包 → 直线段：fit-and-split

凸包是一圈**像素点**（可能几十上百个），怎么变成"6 条边"？

做法叫**迭代端点拟合**（fit-and-split，也可理解为"直线版的 Douglas–Peucker"）：

1. 先假设整段点是**一条**直线，用**总体最小二乘**（TLS）拟合它；
2. 找出**偏离这条直线最远**的点；
3. 如果这个最远距离小于阈值（`splitTol`），就认为这确实是一条直线，输出；
4. 否则在这个点把点集**切成两段**，分别递归做 1~3。

**一个必须注意的坑**：找最远点时**只能在"内部点"里找**。因为每段弧的两个端点是和相邻边的交界（也就是真正的角点），端点离得远只说明"这段弧的尽头是个角"，不说明这段弧不直。如果连端点一起算，遇到"L 形"点集时会直接把整段当直线输出，得到残差几百像素的假直线——我们第一版就是这么错的。

同时还要做两件清理：
- **共线合并**：相邻两段方向差小于 `mergeAngleDeg`（默认 12°）就合并（掩膜边界的锯齿会把一个真角切成两三个 10 像素的伪段）；
- **短段剔除**：比 `minRunLen` 还短的段当噪声丢掉，但至少保留 4 条边。

**TLS（总体最小二乘）**：普通最小二乘是"竖直方向误差最小"，TLS 是"到直线的**垂直距离**平方和最小"，对任意方向的直线都公平，是拟合边界线的标准做法。

### 3.5 顶点 = 相邻两条直线的交点

拿到 6 条边（每条都有"方向 + 一点"），相邻两条**求交点**就得到顶点。为什么这比 Harris 峰值好：

- 每条直线是用**整条边**上几百个像素拟合出来的，个别像素的噪声被平均掉了，所以交点位置精度是**亚像素**的（实测顶点误差均值 0.6 像素、最大 1.1 像素）；
- 顶点**天然有序**（沿多边形一圈的顺序），后面和立方体模型做对应时不会有"哪个点配哪个点"的麻烦；
- 顶点**必然满足"落在两条边的交点上"**这个几何约束，不会像角点响应那样出现"差半个像素但方向乱"的点。

**注意**：直线段数组的顺序必须保持"环绕顺序"。如果在合并两段时把结果随手 push 到数组末尾，顺序就乱了——顶点位置虽然都对，但顺序变成 `hex3,hex0,hex1,...` 这种非环绕序列，任何标注都对应不上，位姿必然错。这是我们在调试中真实踩到的第二大坑。

### 3.6 亚像素精化

掩膜的边界是"像素格子"级的，天然带锯齿。真正的边缘在哪？在灰度**从背景值过渡到目标值**的地方。

做法：对每条边，沿它的**法向**扫描 ±2.5 像素，找到 `|梯度|` 最大的位置，再用**抛物线插值**（用极大值点及其左右两点拟合抛物线，取顶点）得到亚像素偏移；然后把整条边上这些精化后的点再拟合一次直线。

- **梯度 / Sobel**：梯度就是"灰度变化最快的方向和快慢"。它大 ⇒ 那里是边缘。
- **双线性插值**：像素是格子，要取格子中间的值就得插值。
- **稳健剔除**：如果某些采样点的残差过大（比如抓到了旁边的花纹），丢掉它们再拟合；如果精化后方向偏了超过约 10°，直接放弃这次精化，保留原直线。

这一步是把精度从"±1 像素"提到"±0.2 像素"的关键。**有个坑**：如果这条边只有 2 个点（预简化后常见），它的残差初值是 0，那么"精化后残差不能变大"这个判据会永远拒绝精化，顶点就会停在整数坐标上。

### 3.7 从六边形到立方体：哪些顶点连着哪些面

当三个面可见时，立方体的轮廓正好是六边形，而且结构非常规整：

- 六边形的 6 个顶点 = 立方体 8 个角点里**去掉"离相机最近的近角"和"被挡住的那个远角"**剩下的 6 个；
- 近角投影在六边形**内部**（就是图像里那个"Y 字形"交汇点），它和六边形上**隔一个**的三个顶点相连；
- 三个可见面分别是"近角 + 六边形上连续三个顶点"组成的四边形。

注意：程序**不需要**去图像里找那个内部的 Y 型交点——它只用来做校验。位姿完全由 6 个轮廓顶点决定（6 个点非共面，位姿唯一）。

### 3.8 PnP：从 2D 像素解出 3D 位姿

**PnP = Perspective-n-Point**：已知 n 个 3D 点的模型坐标、以及它们在图像上的像素坐标，求相机相对该物体的**位姿**（旋转 + 平移）。

**位姿 = 6 个自由度（6DoF）**：3 个旋转 + 3 个平移。

**相机内参**（intrinsics）是把 3D 点投影成像素的公式参数：`fx, fy`（焦距，单位像素）、`cx, cy`（主点，一般≈图像中心）。**内参必须先标定**，否则所有绝对距离都会错（程序在没内参时会按 `fx≈W/(2·tan30°)` 粗估并打印警告）。

程序里用到的三个 PnP 求解器：

| 求解器 | 用途 | 说明 |
|---|---|---|
| **EPnP** | 6 点求初值 | 快，不需要初值，适合"点比较多"的一般情况 |
| **ITERATIVE**（LM 迭代） | 用 EPNP 结果做初值再精化 | 精度最高，但需要好初值 |
| **IPPE** | **单面 4 点（共面）** | 专门处理共面点，会给出两个解（平面临二义性） |

**一次重要的实测发现**：只用 6 个轮廓点做 PnP，存在**第二个解**——它能把同样 6 个点投到同样的像素位置上，但把立方体整体"翻"过去（可见面变成背面）。这就是著名的**内克尔立方体（Necker cube）二义性**。实测这种错误解会给出法向差 90°、平面偏移差 380 mm 的"看起来合法但完全错误"的结果。

程序用两条与位姿无关的判据把它筛掉：

1. **可见面里必须有一个"朝上"的面**（相机俯视场景这个先验，用 `tiltDeg` 表示相机俯仰角；有 IMU 可以改成用重力方向）；
2. **内部 Y 型棱必须有图像梯度支持**（把近角到三个中间角点的三条线投回图像，看线上是不是真有边缘）。

因为六边形顶点的"起点"和"绕行方向"都是任意的，程序枚举 **6 起点 × 2 方向 × 2 标注 = 24 个假设**，各自解一次 PnP，按 `重投影误差 + 上述判据` 选最优。实测这 24 个里有 12 个是可实现的（误差 ~0.4px），另 12 个是镜像解（误差 ~4.0px），分离度非常好。

**重投影误差（reprojection error）**：把模型按求出的位姿投影回图像，和实际像素比对，偏差的均方根就是 RMS。它是最直观的"这次解得准不准"的指标——本程序实测 **0.26~0.42 像素**。

### 3.9 规范化输出：把结果"摆正"

直接解出来的位姿，它的模型坐标系是"立方体某个角点为原点"的一堆杂乱编号，不好用。所以程序最后统一换算到一个**规范坐标系**：

- 原点 = 立方体**中心**；
- **+z = 朝上那个面的外法向**；
- **+x = 朝图像右侧那个侧面的外法向**（也就是立方体的一条棱方向；这样三个轴都严格是立方体的棱方向，这一点非常关键，见下面"踩坑"）；
- 于是 8 个角点的编号规律是：`j & 1 → x 正负`、`j & 2 → y 正负`、`j & 4 → z 正负`，**j ≥ 4 的 4 个角就是顶面的四个角**。

这样输出的位姿跨帧稳定、可直接解释（比如"偏航角"就是立方体相对图像水平方向的转角）。

**踩坑记录（很重要）**：最初把 +x 取成"图像右方向在顶面上的投影"，想让它更"贴近图像"。结果这个方向和真正的棱方向差了 **3.6°**，于是按 `中心 ± hs·(±ex±ey±ez)` 算出来的 8 个角点整体偏了 **2~4 mm（约 8 像素）**——而位姿本身其实是对的（重投影误差仍 0.42px）。**规范化坐标轴必须严格是物体的几何轴**，不能图方便用别的方向凑。

### 3.10 平面与测距

有了位姿，平面就是几何推论：

- 某个面的**外法向** `n`（单位向量，指向立方体外侧）；
- 面上任一点 `X` 的坐标，得到平面方程 **`n·X = d`**；
- 可见面的 `n` 指向相机，所以 `d < 0`，**相机到该平面的距离 = |d|**。

**测距的两种用法**：

1. **直接量距离**：`r.centerDist`（相机到立方体中心）、`face.distToPlane()`（相机到某个面）。
2. **把任意像素投到平面上**（`pixelToPlane` / `pixelToTopPlane`）：像素 `(u,v)` 决定一条从相机出发的射线，射线方向 = `K⁻¹·(u,v,1)`；射线与平面 `n·X=d` 求交就是那个点的物理坐标。用它可以把"图像上的任意点"变成"桌面上的坐标"，比如抓取点、放置点。

## 4. 专业名词表

| 术语 | 英文 | 一句话解释 | 在本程序里的作用 |
|---|---|---|---|
| ROI | Region of Interest | 感兴趣区域，一个矩形框 | YOLO 框；限定搜索范围，加速并抗干扰 |
| 掩膜 | Mask | 与原图同尺寸的二值图，白=目标 | 分割的输出，后续全靠它 |
| 分割 | Segmentation | 把目标从背景里分出来 | 4 种策略自动选优 |
| Otsu 阈值 | Otsu's method | 自动选一个"类间差别最大"的灰度阈值 | 分割策略 1 |
| 自适应阈值 | Adaptive threshold | 每个小邻域各自算阈值 | 分割策略 2，抗光照不均 |
| Canny | Canny edge detector | 经典的边缘检测算子 | 分割策略 3 的第一步 |
| 形态学闭运算 | Morphological closing | 先膨胀后腐蚀，填小洞、连断线 | 把 Canny 的边界连成封闭区域 |
| 结构元 | Structuring element | 形态学操作的"刷子"形状和大小 | 闭/开运算的核 |
| 轮廓 | Contour | 连通区域的边界像素序列 | 取最大轮廓当立方体 |
| 凸包 | Convex hull | 套住轮廓的橡皮筋绷紧后的形状 | **核心**：让内部花纹完全失效 |
| 凸性 / solidity | Solidity | 轮廓面积 ÷ 凸包面积，∈(0,1] | 质量指标；立方体≈1 |
| 直线拟合 | Line fitting | 用一堆点求最贴合的直线 | 把凸包变成边 |
| 总体最小二乘 | TLS (Total Least Squares) | 最小化到直线的**垂直**距离平方和 | 拟合每条边，各方向都公平 |
| 迭代端点拟合 | fit-and-split | 拟合→找最远点→在彼处剪断→递归 | 凸包→直线段 |
| 残差 / RMS | Residual / RMS | 拟合误差；均方根 | 判断"这段到底直不直" |
| 亚像素 | Sub-pixel | 精度比一个像素更细（如 0.2 像素） | 顶点精度从 ±1px 提到 ±0.2px |
| 梯度 / Sobel | Gradient / Sobel | 灰度变化最快的方向和大小 | 找真实边缘位置 |
| 双线性插值 | Bilinear interpolation | 在两个方向各插一次，取格子中间的值 | 亚像素采样 |
| 抛物线插值 | Parabolic interpolation | 用极值点及左右点拟合抛物线取顶点 | 把极值位置精化到亚像素 |
| 边缘支持度 | Edge support | 假设的多边形有多少比例压在真边缘上 | 选最佳分割/拟合结果的判据 |
| 灭点 | Vanishing point | 3D 中一族平行线在图像上的交点 | 解释"透视下平行线不平行"；可用于校验 |
| 内参 | Intrinsics (K) | `fx, fy, cx, cy`，3D→像素的投影参数 | PnP 必需；不标定则绝对距离不可信 |
| 主点 | Principal point | 光轴与图像平面的交点，≈图像中心 | `cx, cy` |
| 相机坐标系 | Camera frame | 原点在光心，z 向前，x 右，y 下 | 本程序所有物理量的坐标系 |
| 外参 / 位姿 | Extrinsics / Pose | 物体相对相机的旋转 + 平移（6DoF） | 核心输出 |
| 旋转向量 | Rotation vector (rvec) | 用"方向=转轴、模长=转角"表示旋转 | OpenCV 惯例；可用 Rodrigues 转成矩阵 |
| 平移向量 | Translation vector (tvec) | 物体原点到相机原点的位移 | 本程序取立方体中心 |
| PnP | Perspective-n-Point | 已知 3D 模型点 + 2D 像素，求位姿 | 从 6 个顶点解出 6DoF |
| EPNP / ITERATIVE / IPPE | — | 三种 PnP 求解算法 | 分别用于求初值 / 精化 / 单面共面 |
| 重投影误差 | Reprojection error | 模型投回图像与实际像素的偏差 RMS | 最实用的精度指标，实测 0.26~0.42px |
| 内克尔二义性 | Necker cube ambiguity | 同一张立方体图可以有两种 3D 解释 | 用"有朝上的面"+"内部棱有边缘"两条判据排除 |
| 平面方程 | Plane equation | `n·X = d` | 平面信息的标准表达 |
| 法向 | Normal | 垂直于平面的单位向量 | 描述平面的朝向 |
| 偏航角 | Yaw | 绕"朝上轴"的转角 | 立方体相对图像水平方向的朝向 |
| 规范化 | Canonical frame | 把结果换算到统一、可解释的坐标系 | 输出稳定、可跨帧比较 |
| 光线-平面求交 | Ray-plane intersection | 像素→射线→与平面求交 | `pixelToPlane` 测距 |
| PnP 初值 / 迭代 | Initial guess / refinement | 先粗解再迭代精化 | EPNP 给初值，ITERATIVE 精化 |

## 5. 参数怎么调（`cube_pose.yaml`）

| 参数 | 默认 | 含义 | 怎么调 |
|---|---|---|---|
| `cubeSize` | 0.05 | **实物边长(m)** | 拿尺子量。填错一倍，所有距离错一倍（像素误差不变） |
| `tiltDeg` | 20 | 相机向下俯仰角(度) | 只用于判断"哪个面朝上"。相机水平→0~10，俯视桌面→30~45；有 IMU 就用重力方向 |
| `roi_x/y/w/h` | 0 | 固定 ROI | 代码里传 `detect(frame, roi)` 更灵活；写 0 表示不用固定框 |
| `roiPad` | 0.15 | ROI 外扩比例 | 出现"顶点数不是 6"就调大到 0.25 |
| `autoRoi` | 1 | 无 ROI 时自动找候选区域 | 现场有 YOLO 时可关掉省时间 |
| `segMode` | 0 | 0=自动 1=Otsu 2=自适应 3=Canny 4=Lab | 知道哪种稳就写死一个，省一半时间 |
| `minAreaRatio` | 0.02 | 轮廓面积/ROI 面积下限 | 滤小噪点；ROI 很紧时可调小 |
| `splitTol` | 1.2 | 直线拆分残差阈值(px) | 顶点数偏多→调大；偏少→调小 |
| `minRunLen` | 12 | 直线段最短长度(px) | 目标在图像里很小时调小 |
| `mergeAngleDeg` | 12 | 相邻段合并角(度) | 顶点数偏多→调大 |
| `subpix` | 1 | 是否亚像素精化 | 追求精度就开；极端追求速度可关（精度降到 ~1px） |
| `subpixRange` | 2.5 | 亚像素搜索半径(px) | 掩膜边界离真边缘较远时调大 |
| `fx/fy/cx/cy` | 0 | 内参 | **强烈建议棋盘格标定后填** |
| `calibFile` | "" | OpenCV 标定结果 yaml | 与上面二选一 |
| `buildDebugImage` | 0 | 结果里带调试图 | 调试时开 |
| `debugPath` | "" | 顺便把调试图写到该路径 | 调试时填 |
| `verbose` | 0 | 打印分割/拟合诊断 | 现场调参用 |

命令行参数优先级：**命令行 > YAML > 代码默认值**。

## 6. 故障对照表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `顶点数 = 5` / `7` / 更多 | ROI 外扩不够，轮廓被切；或掩膜锯齿把一角切两半 | 调大 `roiPad`；调大 `mergeAngleDeg`；调小 `splitTol`；试固定 `segMode` |
| `顶点数 = 4`（本该是立方体） | 相机几乎正对某个面（此时本来只看得见一个面）；或掩膜只抠出了一个面 | 前者是正常情况（走单面分支）；后者换 `segMode` |
| `重投影RMS` 突然从 0.4px 变成几 px | 某一个顶点检错了（比如把阴影边当成立方体的边） | 看调试图的顶点编号；调 `segMode` / `minAreaRatio` |
| 距离差了几厘米 | 内参没标定（默认是粗估的） | 标定内参填进 YAML |
| 距离成比例地错 | `cubeSize` 填错 | 量实物边长 |
| "朝上的面"判错 | `tiltDeg` 不合适 | 按相机实际俯仰角改；或用 IMU 重力方向 |
| 全图模式找不到目标 | 背景里有别的凸物体抢了分割 | 用 YOLO 的 ROI（推荐）；或固定 `segMode` |
| 目标表面有强花纹导致失败 | 花纹压到棱边造成缺口 | 凸包已经能缓解；再不行调 `subpixRange` 或关掉 `subpix` |
| 耗时太长（>50ms/帧） | 全图 + 4 种分割 + 3 档容差重试 | 用 ROI、固定 `segMode`、降分辨率 |

## 7. 实测精度与适用边界

**测试方法**：`gen_synth.cpp` 生成 4× 超采样渲染的合成立方体（随机位姿，**每个面内部都有黑色毛笔字形花纹，部分花纹故意压在棱上**，背景为带噪声的渐变），真值由渲染时的位姿精确给出；`check_synth.py` 自动比对。

12 个随机位姿、全图与 ROI 两条路径，**全部通过**：

| 指标 | 实测 |
|---|---|
| 6 个轮廓顶点像素误差 | 均值 0.57~0.71 px，最大 ≤1.12 px |
| **8 个角点物理位置误差** | **≤1.2 mm**（距离约 0.28 m） |
| 立方体中心误差 | 0.2~1.3 mm |
| 可见面法向误差 | 0.01~0.29° |
| 平面偏移误差 | 0.2~2.2 mm |
| 重投影 RMS | 0.26~0.42 px |
| 角点 3D 反投影自洽 | ≤0.43 px |
| JPEG（质量 88）损失压缩 | 精度无明显退化 |
| 耗时（i7 桌面机） | 全图 1280×720 稳态 68 ms；**ROI 350×376 稳态 9.2 ms** |

**适用条件**：
- 立方体的**边界与背景对比度足够**（本项目场景满足）；
- 三个面可见（或恰好一个面可见）；
- 边长已知；
- 内参已标定（否则只有相对量可信）。

**已知限制**：
- 强遮挡（边框挡住一个角）会让顶点数变成 5，目前只提示不求解；
- 反光/极低对比度的面可能导致分割失败；
- 单帧图像无法区分"内克尔镜像"，需要相机俯仰先验或 IMU；若有**多帧**，用 `CubePoseDetector::reset()` 之外的状态粘滞 + 上一帧结果做初值会更稳。

## 8. 速查：编译与运行

```bash
# 1) 编译库 + 命令行工具
g++ -O3 -march=native cube_pose.cpp cube_pose_main.cpp $(pkg-config --cflags --libs opencv4) -o cube_pose

# 2) 生成一份带注释的配置模板（所有参数都在里面）
./cube_pose --dump-yaml cube_pose.yaml

# 3) 跑一张图（用 yaml 参数，命令行可覆盖）
./cube_pose --config cube_pose.yaml image.jpg --fx 800 --fy 800 --cx 640 --cy 360 --size 0.05 --debug dbg.png

# 4) 跑相机（Jetson 可用 --gst 传 GStreamer 管线）
./cube_pose --config cube_pose.yaml --camera 0

# 5) 自测：生成带真值的合成图并自动判分
./gen_synth 1 synth_test/s1
python3 check_synth.py synth_test/s1 --size 0.05 --fx 1000 --fy 1000 --cx 640 --cy 360

# 6) 在自己的代码里调用（见 example_use.cpp）
g++ -O3 example_use.cpp cube_pose.cpp $(pkg-config --cflags --libs opencv4) -o example_use
./example_use synth_test/s1.png
```

**最小调用代码**：

```cpp
#include "cube_pose.hpp"

cubepose::CubePoseDetector det;
det.loadConfig("cube_pose.yaml");        // 参数全在 yaml 里

cv::Mat frame = ...;                     // BGR
cv::Rect  roi  = ...;                    // YOLO 的框；没有就传 cv::Rect()
auto r = det.detect(frame, roi);

if (r.ok) {
    double dist = r.centerDist;                    // 距离(m)
    cv::Point3d c0 = r.cornersCam[0];              // 0 号角点物理位置(m)
    for (auto& f : r.faces)                        // 平面：n·X = d
        printf("%s 到相机 %.1f mm\n", f.name.c_str(), f.distToPlane()*1000);
    cv::Point3d p;
    if (r.pixelToTopPlane(cv::Point2d(u, v), p))   // 像素投到顶面 -> 物理坐标
        printf("顶面上的点: %.1f, %.1f, %.1f mm\n", p.x*1000, p.y*1000, p.z*1000);
}
```
